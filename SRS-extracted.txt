1. Introduction
1.1 Purpose
Mobile Shop Manager Pro is an offline desktop application designed to help mobile shop owners manage their
complete business operations digitally without requiring internet connectivity.
The system is built on a modern Tauri + Rust + SQLite stack — delivering a small, fast, cross-platform installer with
native-grade performance and encrypted local data storage.
1.2 Document Scope
This SRS covers all functional requirements, module specifications, the Tauri/Rust architecture, security measures,
database design, and build roadmap for version 1.0.

5. System Architecture
5.1 Tauri Application Model
Tauri applications consist of two processes that communicate via an IPC bridge:
┌─────────────────────────────────────────────────────────┐ │ FRONTEND PROCESS (WebView2 —
Chromium on Windows) │ │ React + TypeScript + Tailwind CSS │ │ UI rendering, user interaction, state
management │ └──────────────────────┬──────────────────────────────────┘ │ Tauri
IPC — invoke() / listen() ┌──────────────────────▼──────────────────────────────────┐ │ BACKEND
PROCESS (Native Rust binary) │ │ Business Logic → Service Layer → Repository Layer │
└──────────────────────┬──────────────────────────────────┘ │ rusqlite / sqlx
┌──────────────────────▼──────────────────────────────────┐ │ DATABASE (SQLite + SQLCipher — AES-
256 encrypted) │ │ Single encrypted .db file — zero configuration │
└─────────────────────────────────────────────────────────┘
5.2 How Tauri IPC Works
The frontend (React) cannot directly access the database or filesystem. Every database operation is requested through
a Tauri Command — a Rust function tagged with #[tauri::command]. This enforces security and business logic at the
Rust layer.
// Frontend — React calls a Rust function const result = await invoke("create_sale", { saleData: payload }); //
Backend — Rust handles the command #[tauri::command] fn create_sale(sale_data: SaleDto, state:
State<AppState>) -> Result<SaleResult, AppError> { sale_service::create(sale_data, &state.db) }

7. License Management System
7.1 Overview
The license system is fully implemented in Rust. It works 100% offline — no internet required for activation or
validation. Each license key is cryptographically tied to the hardware it is activated on.
7.2 Hardware Fingerprint (Rust)
// Rust — collect hardware IDs let cpu_id = get_cpu_id(); // WMIC or /proc/cpuinfo let disk_id =
get_disk_serial(); // First disk serial number let mac_addr = get_mac_address(); // First non-loopback MAC //
Combine and hash let fingerprint = sha256(cpu_id + disk_id + mac_addr); // License payload (AES-256 encrypted) let
payload = LicensePayload { shop_name: "Noor Mobile Shop".to_string(), license_type:
LicenseType::Professional, expiry_date: NaiveDate::from_ymd(2027, 8, 26), fingerprint: fingerprint.clone(), }; let
license_key = aes256_encrypt(serialize(payload), SECRET_KEY);
7.3 Validation Flow
● On first run: user enters license key → Rust decrypts → checks fingerprint matches current hardware
● On every startup: Rust silently re-validates key against hardware fingerprint
● Mismatch: returns Err("License not valid on this device") → access denied
● Expiry: Rust compares expiry_date to today → shows renewal prompt after expiry
● Grace period: 7 days read-only access after expiry before full lockout
● License stored in AES-256 encrypted file in AppData — cannot be manually edited

10.2 Key Design Rules
● All tables use INTEGER PRIMARY KEY (SQLite auto-increment rowid alias)
● IMEI column has UNIQUE constraint at DB level — duplicate rejected even if Rust check is bypassed
● All monetary values stored as INTEGER cents (e.g., 15000 = Rs 150.00) — avoids floating-point precision issues
● Soft delete pattern — records have is_deleted BOOLEAN, never physically removed (preserves history)
● activity_log is append-only — no UPDATE or DELETE allowed on this table (enforced in Rust)
● Foreign key constraints enabled via PRAGMA foreign_keys = ON on every connection

12. Error Handling and Logging
12.1 Rust Error Handling
All Tauri commands return Result<T, AppError>. AppError is a custom Rust enum with variants for every error type. The
frontend receives a structured JSON error — never a panic or raw exception.
#[derive(Debug, Serialize)] enum AppError { DatabaseError(String), DuplicateImei(String), LicenseInvalid,
PermissionDenied, ValidationError(String), PrintError(String), }
12.2 Logging with tracing
Level When Used Example
INFO Normal events User logged in, sale created, backup completed
WARN Non-critical issues Low stock reached, license expiring in 7 days
ERROR Caught Rust errors DB write failed, print error, file not found
DEBUG Development only SQL queries, IPC payload details (disabled in release
build)
● Log files: AppData\MobileShopPro\logs\app-YYYY-MM-DD.log
● Daily rolling files — auto-delete after 30 days
● Release builds: INFO level and above only — no debug noise for customers
● Error dialog shows reference code matching the log entry — easy remote support

16. Conclusion
Mobile Shop Manager Pro is built on a modern, production-grade Tauri + Rust + SQLite stack that delivers a small
