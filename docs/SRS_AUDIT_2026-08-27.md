## B. Current Architecture Report
- **Backend (Rust/Tauri):** Clean 4-layer split — `commands` (IPC façade + permission checks) → `services` (business rules) → `repositories` (SQL) → `models`. `errors::AppError`. `security` (Argon2id, in-memory `SessionState`). `database::migrations` (16 tables). 25+ `#[tauri::command]` including settings/backup/activity.
- **Frontend:** React + TS + Tailwind + zustand stores (`session`, `sales`, `inventory`, `members`, `suppliers`, `expenses`, `reports`, `settings`). Layout with sidebar; pages: Login, Dashboard, Inventory, Sales, Members, Payments, Expenses, Reports, Suppliers, Settings. Modal-based forms.
- **Verification state:** 57/57 backend tests pass; `npm run build` clean; Tauri build clean.
- **Strengths:** solid service/repository separation, Rust-side RBAC + validation, activity logging, functional core sale/inventory/member/expense flows, working tests.
- **Core gaps vs SRS:** no license system, no SQLCipher/AES-256 DB encryption, no JWT, money as REAL, no purchases/brands/customers/PTA/warranty, no Luhn, no PDF/thermal printing, no sale returns, no credit-installment module, no supplier dues, only 4 report queries (not 10 PDF reports), plain-string errors, env_logger not tracing, no auto-backup/encrypted archive.

## C. Current UI/UX Problems
1. No license gate — app opens without activation; SRS requires first-run activation + expiry.
2. English USD formatting (`currency: "USD"`) in a Pakistani shop context; SRS examples use Rs — inconsistent currency localization.
3. No PDF/print for receipts or any report — receipts only render in a browser modal; cannot print/email invoices per SRS.
4. No printer support (A4/thermal) — no receipt printing at POS.
5. Sales form lacks inline customer creation, percentage/flat discount selector, and clear Credit/Partial balance breakdown.
6. Dashboard lacks today's sales/profit, supplier dues, and Recharts trend; recent activity isn't clickable sales.
7. Reports section is minimal (period summary + category expenses), no date-range sales/profit/dues PDFs.
8. No low-stock/overdue cross-module alert center (only a dashboard banner).
9. Members vs Customers / Inventory vs Products terminology confuses against SRS.
10. No user management or settings for brands/printer/invoice/license in Settings screen.
11. No sale return/void workflow in Sales UI.
12. No instalment/credit statement UI, no overdue flagging.

## D. Recommended New Architecture
Adopt the SRS architecture while keeping the working service/repository shell:
1. **DB layer:** SQLCipher (via `rusqlite-cipher`), WAL mode, `foreign_keys=ON`, migrate money fields to **INTEGER cents**, add versioned SQL migration files.
2. **Security:** Add JWT (HS256) session over the existing `SessionState`; expand `AppError` to SRS variants + structured JSON serialization; add `LicenseInvalid`/`DuplicateImei`/`PrintError`.
3. **New modules:** `license.rs` (fingerprint + AES key validation), `pdf.rs` (printpdf invoice/report/statement), `print.rs` (escpos-rs thermal), `purchase.rs`, `customer.rs` (rename members→customers with CNIC/total_balance), `credit.rs` (installments + overdue), `backup.rs` (aes-gcm archive + auto schedule).
4. **Add tables:** `brands`, `products` (with `product_type` for mobiles/accessories, `imei UNIQUE`, `warranty_days`), `customers` (rename), `purchases`/`purchase_items`, `license`. Keep `sales`/`sale_items`/`payments`/`expenses`/`activity_log`/`settings`.
5. **Logging:** Replace `env_logger` with `tracing`+`tracing-subscriber` rolling daily file logs.
6. **Frontend:** Add Recharts; route to ~16 screens (see F); add printer/license/settings panels.
